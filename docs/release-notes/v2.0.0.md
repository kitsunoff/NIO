# v2.0.0 — teardown on NixCluster deletion

## Breaking changes and upgrade notes

- **Deleting a `NixCluster` now tears the real cluster down.** The new
  `spec.deletionPolicy` field defaults to `Teardown`: on `kubectl delete`, NIO keeps
  the finalizer, stops the converge cron, runs `nixclusterctl <cluster> teardown` as an
  owned `NixJob`, and releases the object only after the teardown succeeds. Every
  member leaves its clusters, loses the cluster state and is switched back to its
  base NixOS configuration.

  The default also applies to `NixCluster` objects created before the upgrade. To
  keep the previous behaviour (only the Kubernetes objects go away, the hosts keep
  running), set the policy **before** deleting:

  ```bash
  kubectl patch nixcluster NAME --namespace NAMESPACE --type merge \
    --patch '{"spec":{"deletionPolicy":"Retain"}}'
  ```

  A deletion that is stuck on a failing teardown (condition `TeardownFailed`) can be
  released the same way.

- **Requires a nixcluster revision with the `teardown` command.** A flake pinned to an
  older nixcluster has no `teardown`, so the teardown job fails and the deletion stays
  blocked until the policy is switched to `Retain` or nixcluster is updated.
  Use nixcluster `v0.1.0` or later.

## Fixes

- The manager image is now Alpine-based and ships `git` and `ssh`. The distroless
  image had no `git`, so every NixCluster or Nix workload that tracks a branch
  stalled resolving the ref and never converged.
- Go modules and the Go toolchain are updated past newly published advisories in
  x/net, x/crypto, x/text, grpc, the otel SDK and the Go standard library.
